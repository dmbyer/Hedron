# Content Authoring (Blazor Editor)

> The offline Blazor Server editor for browsing, filtering, creating, editing, deleting, renaming, and applying world content definitions. **Status:** live (content-tooling platform WP-2/WP-3; area filters + referential integrity + delete; blueprint-id rename + choose-at-creation).

## What it is / does

`Hedron.Web` is a `Microsoft.NET.Sdk.Web` Blazor Server application that boots the engine via the shared `CompositionRoot.Register` (identical DI to `Server`) with a **bootstraps-only** hosted-service composition — content load and registry validation only; no telnet listener, no heartbeat, no persistence flush. It binds loopback-only (`http://127.0.0.1:<port>`); no auth system is built for v1.

The editor provides: a content browser (list all four kinds, **filterable by area**), a definition editor per kind (load → edit fields → validate → save, with **lookup-driven selection fields** and **delete**), a "Create new" flow per kind, an **Integrity** page (broken-link sweep), and an "Apply to live (reload)" action. All read/list/load/validate/write/delete/reference logic lives in [`IContentDefinitionCatalog` / `IContentReferenceIndex`](content-tooling.md) — Blazor components are thin adapters that choose filter values and bind fields, never containing authoring or reference-resolution logic (INV-8 extended to the new surface).

## How it works

The Blazor host is the presentation tier over the same content-tooling systems the telnet commands call:

1. **Browse + filter.** A page calls `IContentDefinitionCatalog.List(kind)` and renders id | name | short-desc. Per-kind **counts are read once per reload into page state**, never per rendered tab — a catalog call inside a render loop re-asks on every render pass. The toolbar also carries a **Refresh from disk** action (`Invalidate()` + reload) for content written outside this process; see [`content-tooling.md`](content-tooling.md#read-semantics--cached-coherent-for-catalog-mediated-writes). Each `ContentSummary` carries its resolved `AreaBlueprintId` (room → its `AreaId`; item/mob → spawn-room → area, computed catalog-side), so the page renders an **area filter** (defaulting to "all", always returnable to "all") that hides non-matching rows. Filtering is component-side over the catalog-computed projection — the component resolves nothing.
2. **Load / create.** The editor calls `Load(kind, blueprintId)` or `CreateNew(kind, name)` (ad-hoc id from `AdhocBlueprintId`). The returned `ContentDefinition` binds to the form. No live entity is created. The New form's blueprint-id field (the shared `BlueprintIdField` component) lets the author type a deliberate id instead — blank still falls back to the adhoc id; a save routes through `CreateAsync`, the create-guarded write (format + uniqueness, refuses a bad or taken id, no overwrite) rather than the unguarded `SaveAsync` edits use. **Editing that field rekeys the in-progress definition via `WithBlueprintId` — it must never call `CreateNew`,** which mints a fresh default and silently discards every other field the author has filled in. That defect shipped in all four editors and is now held by an architecture guard (`Editors_do_not_recreate_the_definition_when_the_blueprint_id_changes`), because it had survived review four times.
3. **Edit with selection fields.** The designer mutates form fields; the form holds a working copy. Selection fields are lookup-driven, populated from `List(Area)` / `RoomsInArea(...)`: the room editor offers an **area picker** and a **filterable exit room-lookup** per direction (extracted into shared `RoomBasicsFields`/`RoomExitsEditor` Razor components, also consumed by the grid editor — step 10); the item/mob editors offer a **cascading area→room picker** for the spawn room. An optional **bidirectional** toggle on the room editor routes the save through `SaveRoomAsync(room, bidirectional: true)`, which also writes the inverse exit on each target room (warn-and-skip on conflict).
4. **Save (validate-then-write, warn-but-allow).** `SaveAsync(definition)` runs `IContentValidator.Validate`; structural failure → `ContentWriteResult.Failed(errors)`, **no file written**. On structural pass it checks cross-references via `IContentReferenceIndex.BrokenFor`; any dangling ref becomes a non-blocking **warning** in `ContentWriteResult.Warnings` and the YAML is still written through the matching `I*ContentWriter` (atomic tmp → rename). The page renders warnings distinctly from blocking errors. The live world is untouched.
5. **Delete (cascade-clear).** A two-step delete on a browser row or editor calls `DeleteAsync(kind, id)`: the catalog cascade-clears every referrer (via `IContentReferenceIndex.Referrers`) and removes the YAML file — **file-only, no live world / no SQLite** (INV-22/23). The page renders the `ContentDeleteResult` cascade summary.
6. **Rename (cascade-rewrite).** The editor's blueprint-id display (the shared `BlueprintIdField` component) offers a **Rename** action revealing an inline id field; confirming calls `RenameAsync(kind, oldId, newId)` — the structural sibling of delete: `ValidateBlueprintId` + a uniqueness check refuse a malformed or already-taken id (no write, `oldId` file intact); on pass, a fresh `newId` file is written carrying the definition's full state (self-referential fields rewritten `oldId → newId`), every external referrer is cascade-*rewritten* via the same `IContentReferenceIndex.Referrers` traversal delete uses, and the `oldId` file is deleted. **File-only** (INV-22/23) — out-of-YAML advisories (persistent player/item locations, `World:StartingRoomBlueprintId`) surface as warnings, never a write. On success the page navigates to the new id's edit route.
7. **Integrity sweep.** The Integrity page sweeps for broken links via `IContentReferenceIndex.SweepBroken()` and tabulates each one (source kind, id, field/direction, missing target) with edit links — the offline "assurance" surface before reload. The sweep runs off the circuit thread (step 12).
8. **Apply to live.** The "Apply" action calls `IWorldContentLoader.ReloadAsync()` — [Flow 5 (content reload)](../../architecture/flows/flow-05-content-reload.md). This is a full rebuild: world content is torn down and re-spawned from YAML (players preserved), so edits to existing entities take effect and runtime instance state resets.
9. **Standards page (sim-1).** A sibling page, `/standards`, edits the balance-standards document via `IBalanceStandardsStore` instead of the catalog — deliberately outside `IContentDefinitionCatalog` (a single criteria file has no blueprint id, no delete-cascade). It mirrors the same validate-then-write, refuse-vs-warn, atomic-write posture as steps 4–5 above, but has **no `reload` leg**: a saved edit takes effect on the next host start (restart-to-apply), stated on the page. See [`../progression/power-budget-system.md`](../progression/power-budget-system.md) for what the document holds.
10. **Visual grid area editor (world-editor-grid).** `/area/{blueprintId}/grid` (linked from the area editor and the browser's area rows) renders one area's rooms on a 2-D grid, one Z-layer at a time. It loads the area's rooms and calls `IAreaLayoutSystem.Propose` for a deterministic BFS layout proposal covering any room that lacks authored `X/Y/Z` coordinates (rendered as dashed ghost cells; anchored rooms render solid). Every grid action is a composition of the same catalog verbs steps 2–6 already use — create (`CreateNew` + `SaveRoomAsync`), connect (set exit + `SaveRoomAsync(bidirectional: true)`), edit/delete/rename (the shared `RoomBasicsFields`/`RoomExitsEditor`/`BlueprintIdField` detail panel + `SaveAsync`/`DeleteAsync`/`RenameAsync`) — plus one earned verb, `RemoveRoomExitAsync`, for one-click bidirectional disconnect (an edge tab or exit badge). An **Apply layout** action (shown while ghost cells exist) calls `IAreaLayoutSystem.ApplyProposalAsync`, which re-derives the proposal from disk and writes coordinates for every still-coordless room, best-effort per room. Coordinates are advisory authoring layout, not an exit constraint: adjacent-cell exits render as edge tabs; vertical, non-adjacent, or cross-area exits render as badge chips; a coordinate collision (two rooms in one area at the same cell) renders as a flagged cell, backed by the same `RoomCoordinateCollisions` helper the boot-time registry-validation warning uses. No JS asset — click-based interaction over the same `IContentDefinitionCatalog` writes, v1. See [`content-tooling.md`](content-tooling.md#iarealayoutsystem--visual-grid-area-editor) for `IAreaLayoutSystem`.

11. **Authoring throughput affordances (authoring-editor-repair).** All four editors carry a **Save & create next** action: it saves, then re-arms the same page as a New form seeded by `CreateNextFrom` — the catalog decides what carries forward per kind, so no component holds authoring policy. It re-arms *in place* rather than navigating, since the carried-forward definition cannot survive a route change without cross-page state. Alongside it: the first field autofocuses, **Enter** saves and **Esc** returns to the browser (multi-line fields stop keydown propagation so Enter still inserts a newline there), every row/cell loop carries `@key` so Blazor diffs by identity rather than position, and the room exit pickers debounce their per-direction filters — six pickers each re-filtering the whole room list per keystroke, so the component suppresses the render Blazor would otherwise do per event and repaints only on the pause.
12. **Integrity sweep runs off the circuit thread.** The Integrity page delegates to `ContentIntegritySweepService` (`Hedron.Web/Services/`), which runs `IContentReferenceIndex.SweepBroken()` and `IBalanceAuditSystem.Audit()` on a background task and exposes a status snapshot the page polls — both are corpus scans, and neither reads through the catalog's index, so this makes the page **non-blocking, not fast**. It is progress-only (no queue, no cancellation), which is why it does not fire the `SimulationRunService` generalization trigger recorded in [`../../architecture/08-blazor.md`](../../architecture/08-blazor.md); the bulk conformance apply on that same page still blocks the circuit and remains the candidate.

The full sequence is [Flow 29 (content-tooling journey)](../../architecture/flows/flow-29-bulk-content-generation.md).

## Host composition

Split hosted-service registration is the seam that lets one engine DI serve multiple host shapes (INV-19):

- `CompositionRoot.Register(IServiceCollection, IConfiguration)` — **pure DI** (all `Add*Module` extensions; no `AddHostedService`).
- `AddGameplayHostedServices` — telnet host: TelnetServer + HeartbeatBackgroundService + PersistenceFlushTimer + bootstraps.
- `AddContentBootstrapHostedServices` — web host: content-load bootstrap + registry-validation bootstrap only.

`Hedron.Web/Program.cs` calls `Register` + `AddContentBootstrapHostedServices` + Blazor services. `Server/Program.cs` calls `Register` + `AddGameplayHostedServices`. Both are sealed at composition time; `Register` never grows a host-role flag.

## Interface

The editor's backing seam is in [`content-tooling.md`](content-tooling.md):

- [`IContentDefinitionCatalog.cs`](../../../Core/Modules/Authoring/Systems/IContentDefinitionCatalog.cs) — the thin facade all editor pages call (list/load/save/delete/create).
- [`IContentReferenceIndex.cs`](../../../Core/Modules/Authoring/Systems/IContentReferenceIndex.cs) — the declared-edge reference model behind filtering associations, delete cascade, save warnings, and the Integrity sweep.
- [`IContentValidator.cs`](../../../Core/Modules/World/Systems/IContentValidator.cs) — per-edit and per-write structural validation, returns `ValidationReport`.
- [`IAreaLayoutSystem.cs`](../../../Core/Modules/Authoring/Systems/IAreaLayoutSystem.cs) — the grid editor's deterministic auto-layout proposal and bulk apply.

## Blazor discipline

See [`../../architecture/08-blazor.md`](../../architecture/08-blazor.md) for the Blazor architecture rules. Key points:

- Blazor components are **presentation-only** — all logic lives in the catalog/validator (the fat-component analogue of a fat command, INV-8).
- The web host composes **no** `bus.Subscribe` wiring; it runs no gameplay handlers.
- Loopback-only for v1. A non-local bind requires authn/z (tracked in [`../../roadmap/backlog.md`](../../roadmap/backlog.md)).
- This host is the foundation the deferred player-client and live-admin suites will inherit (same process, same engine DI, `ISession`/SignalR seam pre-shaped).
