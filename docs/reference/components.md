# Components Reference

Living catalog of every ECS component. **Update this file whenever a component is added, removed, or materially changed.**

Source of truth: `Core/ECS/Components/` (cross-cutting) and `Core/Modules/<Feature>/Components/` (feature-owned).

> Shape-level documentation only. For design rules (prototype vs instance, archetypes), see [../architecture/02-ecs.md](../architecture/02-ecs.md).

---

## Cross-cutting components

All cross-cutting components live under `Core/ECS/Components/`.

| Component | Shape | Owned by archetypes |
|---|---|---|
| `IdentityComponent` | `Name`, `ShortDescription`, `LongDescription`, `Tier`, `WasAutoGenerated` | every archetype |
| `TransformComponent` | parent/child, `RoomId`, `AreaId` | every archetype except Custom |
| `PrototypeComponent` | `CacheType`, `PrototypeSource`, `PersistenceKey` | every archetype |
| `EffectsComponent` | active effects list | every archetype |
| `AttributesComponent` | `Might`, `Finesse`, `Will`, … with `EquipmentBonuses`, `DeathPenaltyModifier` | Player, Mob |
| `PoolsComponent` | HP / Stamina / Energy (current + max) | Player, Mob |
| `CurrencyComponent` | copper, silver, gold, vita, menta, astra | Player, Mob |
| `SkillsComponent` | learned skills, levels, improvement tracking | Player, Mob |
| `QualitiesComponent` | misc qualities / tags | Player, Mob |
| `InventoryComponent` | unequipped carried items, capacity | Player, Mob, Room (ground items) |
| `EquipmentComponent` | items worn in slots (`Head`, `Torso`, `OneHandedWeapon`, …) | Player, Mob |
| `PlayerDataComponent` | connection ref, privilege level, state | Player only |
| `PlayerConfigurationComponent` | prompt template, preferences | Player only |
| `MobDataComponent` | behavior flags, level, level effects | Mob only |
| `ItemDataComponent` | `Slot`, `Rarity`, `Material`, `Value`, `Behavior` | every Item archetype |
| `WeaponDataComponent` | `DamageType`, `MinDamage`, `MaxDamage`, `WeaponType` | Weapon |
| `PotionDataComponent` | `PoolRestoration`, `Effect` | Potion |
| `ContainerDataComponent` | capacity, contained entity list, access permissions | Room, Area, Storage |
| `RoomDataComponent` | `Exits`, `IsShop`, `Environment`, `IsSafe`, `LightLevel` | Room |
| `AreaDataComponent` | `RespawnRate`, `SpawnableMobs`, `CuratedItems`, `Weather`, `PvP` | Area |

## How to add a new component

Use the `add-component` skill — see `.claude/skills/add-component/SKILL.md`. Short version:

1. Decide if it's cross-cutting or module-owned.
2. Add the `.cs` file under the correct folder (name `*Component.cs`).
3. Implement `IComponent` with **pure data only** — no logic.
4. Update this catalog (add a row to the appropriate table).
5. If required by an archetype, update `Core/ECS/ArchetypeRegistry.cs` and [archetypes.md](archetypes.md).

Invariants to preserve:
- Components are pure data. No methods that perform work.
- Do not call back into `EntityService` / `EcsManager.World` from a component.
- Components may be struct or class. Prefer class (current codebase convention) unless profiling calls for struct.
