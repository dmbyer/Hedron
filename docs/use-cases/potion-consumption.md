# Potion Consumption

**Status:** partial
**Actors:** Player
**Module:** `Core/Modules/Items/` / `Core/Modules/Effects/`

## Description

A player drinks a potion. The potion restores one or more pools (HP/Stamina/Energy) and applies a temporary effect with a duration. The potion is then consumed (removed from inventory and cache).

## Preconditions

- Player has a potion matching the name in `InventoryComponent`
- Player state is Active or Combat
- `PotionDataComponent.PoolRestoration` and/or `PotionDataComponent.Effect` are populated

## Postconditions

- Affected `PoolsComponent` values are increased (clamped to max)
- Temporary effect appears in `EffectsComponent` with its duration
- Potion entity is removed from `InventoryComponent` and destroyed from both instance and prototype caches (for autogenerated single-use potions) or just instance cache otherwise
- Player receives a feedback line per restoration and effect

## Main flow

1. `drink <potion>` command → item handler
2. `InventorySystem.HasItem` — locate the potion
3. Domain potion-use system reads `PotionDataComponent`
4. `PoolsSystem` applies restorations
5. `EffectTracker.ApplyEffect` registers the temporary effect
6. `InventorySystem.RemoveItem` + cache eviction of the potion
7. Handler publishes `ItemDestroyedEvent` + a restoration notification

## Events fired

- `ItemDestroyedEvent` — potion consumed
- `SpellEffectAppliedEvent` — if the potion carries an effect (shared with spell system)
- `PoolsChangedEvent` _(planned)_ — for UI updates

## Systems / handlers

- `EffectTracker` (core)
- `InventorySystem` (domain)
- A `PotionSystem` or reusable `ConsumableSystem` (domain) for rule: "who can drink what"
- `InventoryHandler` / `ItemHandler`
- `NotificationHandler`
