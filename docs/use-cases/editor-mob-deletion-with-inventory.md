# Editor: Mob Template Deletion with Inventory

**Status:** planned (revisit when admin-tooling scope is settled — see Ticket B in [../roadmap/plan.md](../roadmap/plan.md))
**Actors:** Administrator, admin tool (UI or command)
**Module:** Admin tooling + `Core/Modules/WorldEditing/`

## Description

An administrator deletes a mob **template** that has items assigned to its `InventoryComponent`. Carried item templates must be handled per policy (keep, delete if autogenerated, or orphan-quarantine). Area/room template references pointing at the mob must be scrubbed, and any live entities spawned from the deleted template must be destroyed.

## Preconditions

- Admin has required privilege
- Mob template exists in `TemplateRegistry`
- Mob may have inventory item template references
- No live instances of the mob are currently in combat (otherwise, refuse or schedule)

## Postconditions

- Mob template removed from `TemplateRegistry` and disk
- Inventory item templates handled per policy (delete autogenerated; keep shared; quarantine orphans)
- All area/room template references to the mob are cleaned
- Any live entities spawned from this template are destroyed
- UI reflects the removal

## Main flow

1. Admin selects mob in the admin tool → "Delete"
2. `WorldEditingSystem.PlanMobTemplateDeletion(templateId)` → manifest:
   - Referencing area/room templates
   - Inventory template references with their autogenerated flags
   - Live entities spawned from this template
3. Admin confirms
4. `WorldEditingHandler` orchestrates:
   - Destroy every live entity via `EntityService.DestroyEntity`
   - Scrub the mob reference from each area/room template's spawn list
   - For each inventory template: apply policy (delete / keep / quarantine)
   - Remove mob template from `TemplateRegistry`
   - Mark disk paths for removal → `PersistenceHandler` flushes
5. Handler publishes `MobTemplateDeletedEvent`
6. UI refreshes

## Events fired

- `MobTemplateDeletedEvent` _(planned)_
- `EntityDestroyedEvent` — for each live entity destroyed
- `TemplateReferenceScrubbedEvent` _(planned)_ — for each referencing template

## Systems / handlers

- `WorldEditingSystem`, `EntityService`, `TemplateRegistry`, `PersistenceHandler`
- `WorldEditingHandler` — orchestrator

## Design notes

- **Autogenerated vs authored items** is a flag on the item template. The deletion policy is "delete autogenerated, keep authored, quarantine shared-but-now-orphaned."
- **Reference scrubbing** lives in `WorldEditingSystem` — not in every handler that could host a mob reference. One source of truth.
- **Live entities die immediately.** An admin edit is an authoritative rewrite of world state.
